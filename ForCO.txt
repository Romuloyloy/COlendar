Hi! This pass adds Calendar Month View v1.

What changed:
- `/calendar` now shows a visual monthly calendar grid.
- The Calendar page has previous month, Today, and next month controls.
- Users can select a day from the month grid.
- Events appear inside day cells as compact time/title indicators.
- The selected-day panel shows events for the chosen date.
- Creating an event defaults to the selected date.
- Existing edit and archive behavior still works.
- Archive now asks for confirmation before hiding an event.
- The frontend reuses the existing date-range Calendar API for visible month data.
- Added a backend test confirming archived events are excluded from date-range results.
- Updated `README.md` with the month view behavior and current limitations.

How to test it:
1. `docker compose up --build -d`
2. `docker compose exec backend alembic upgrade head`
3. `docker compose exec backend alembic current`
4. `docker compose exec backend pytest`
5. `docker compose exec frontend npm run build`
6. Open `/calendar`.
7. Navigate previous/next month and return to Today.
8. Select a day, create an event, edit it, and archive it.
9. Confirm dashboard upcoming events, planning, Quick Add, and Global Search still work.

What success looks like:
- Calendar shows a month grid with scheduled events in day cells.
- Month navigation updates the visible calendar.
- Selected-day events are clear.
- Created events appear in the correct day cell.
- Edited events update normally.
- Archived events disappear from normal calendar views.
- Backend tests and frontend build pass.

Known limitations:
- No external sync.
- No recurring calendar events.
- No reminders or notifications.
- No drag-and-drop event moving.
- No advanced week/day views.
- Tasks and events are still separate product concepts.

Recommended next phase:
- Add lightweight browser QA around event creation/edit/archive in the month grid.
- Later consider a focused week/day visual view spec if the month view feels stable.
