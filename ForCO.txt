Hi! This added Widget Foundation v1.

What changed:
- Refactored the fixed dashboard so it renders through code-defined widget definitions.
- Added formal widget-like dashboard components:
  - `TodayOverviewWidget`
  - `QuickActionsWidget`
  - `DailyTasksWidget`
  - `WeeklyTasksWidget`
  - `RecentNotesWidget`
  - `UpcomingEventsWidget`
  - `TrackerSummaryWidget`
  - `PlanningSummaryWidget`
- Added lightweight shared widget types in `frontend/src/features/dashboard/widget-types.ts`.
- Added a code-only widget registry in `frontend/src/features/dashboard/dashboard-widget-registry.ts`.
- Added a small `WidgetRenderer` in `frontend/src/features/dashboard/WidgetRenderer.tsx`.
- Kept the dashboard fixed and non-customizable.
- Kept dashboard task completion behavior wired through the existing task APIs.
- Added a dashboard Quick Actions widget with links to Search, Tasks, Notes, Calendar, Planning, and Tracker.
- Quick Actions can also open the existing app-shell Quick Add panel.
- Updated README.md with the Widget Foundation v1 overview, current limits, future direction, and Windows PowerShell commands.

How to test it on Windows:
1. Start Docker Desktop.
2. Open PowerShell in the repo root.
3. Run `docker compose up --build -d`.
4. Run `docker compose exec backend alembic current`.
5. Run `docker compose exec backend pytest`.
6. Run `docker compose exec frontend npm run build`.
7. Open `http://localhost:3000`.
8. Check existing pages: `/notes`, `/tasks`, `/calendar`, `/tracker`, `/planning`, and `/search`.
9. Use dashboard checkboxes for daily tasks and scheduled weekly task occurrences.
10. Use dashboard Quick Actions to open Quick Add and navigate to Search.

What success looks like:
- Frontend loads at `http://localhost:3000`.
- Existing pages still load and behave normally.
- Dashboard visually still feels like the same fixed dashboard.
- The dashboard now has a clear widget registry and renderer internally.
- Quick Add still works from the app shell, `Ctrl+K`, and the dashboard Quick Actions widget.
- Global Search still works at `/search`.
- Backend health works at `http://localhost:8000/health`.
- Database health works at `http://localhost:8000/health/db`.
- Backend tests and frontend build pass.

What remains intentionally postponed:
- No backend widget APIs.
- No widget tables or migrations.
- No persisted widget instances.
- No dashboard customization.
- No sheets or no-scroll 4x2 sheet UI.
- No drag-and-drop or resizable dashboard layout.
- No auth, AI, semantic search, pgvector, external integrations, reminders, notifications, or advanced analytics.

Recommended next phase:
- Add simple result deep links/highlighting for Search, or add a small widget contract document before starting any persisted dashboard customization work.
