Hi! This pass adds Task/Event Concept Cleanup v1.

What changed:
- User-facing UI now says One-time Tasks instead of Daily Tasks.
- Backend route/table names stay compatible: `/api/tasks/daily` and `daily_tasks` are legacy/internal names for one-time dated tasks.
- One-time tasks now support optional `planned_time`, `due_date`, and `due_time`.
- Tasks remain completable things; calendar events remain scheduled things that happen at a date/time.
- Planning continues to combine one-time tasks, weekly tasks, and events without merging them.
- Quick Add can create one-time tasks with planned date, optional planned time, optional deadline, and category.
- Weekly Task Quick Add still works.
- Dashboard, sheets, planning, and search wording now use One-time Tasks.
- One-time task widgets/lists show planned time and due metadata when present.
- Added Alembic migration and backend tests for the new optional fields.

How I test it:
1. `docker compose up --build -d`
2. `docker compose exec backend alembic upgrade head`
3. `docker compose exec backend alembic current`
4. `docker compose exec backend pytest`
5. `docker compose exec frontend npm run build`
6. Open `/`, `/notes`, `/tasks`, `/calendar`, `/tracker`, `/planning`, `/search`, and `/sheets`.
7. Create a one-time task from Tasks and Quick Add with planned time and due date/time.
8. Confirm weekly task Quick Add still works.
9. Confirm task category filters, dashboard customization, sheet configs, and duplicate sheet widgets still work.

What success looks like:
- Existing task behavior still works.
- One-time task optional fields save, update, clear, and appear in list responses.
- Dashboard, sheets, planning, and search still include tasks correctly.
- Calendar events remain separate and do not get task checkboxes.
- Alembic reports the latest migration as head.
- Backend tests and frontend build pass.

Limitations:
- No full task/event unification.
- No event recurrence.
- No advanced, monthly, or bi-weekly recurrence.
- No reminders or notifications.
- No priority, subtasks, drag-and-drop, resizing, auth, AI, or integrations.
- The API still uses `/api/tasks/daily` until a future compatibility-safe rename phase.
- Due dates are flexible metadata and are not restricted relative to planned date.

Recommended next phase:
- Add a small product-language cleanup pass for API docs and variable aliases if desired.
- Add lightweight browser QA around task creation/editing with planned time and deadlines.
- Later consider compatibility aliases like `/api/tasks/one-time` without removing `/api/tasks/daily`.
