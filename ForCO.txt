Hi! This pass implements UI Foundation v1.

What changed:
- Added the first shared visual token layer in `frontend/app/globals.css`.
- Established a soft minimalist workspace direction: warm off-white backgrounds, pale cream surfaces, muted sage/teal primary actions, lavender/sage accents, soft rose danger actions, rounded cards, gentle shadows, and low-contrast borders.
- Expanded shared frontend UI primitives in `frontend/src/components/ui.tsx` with `AppButton`, `AppCard`, `Badge`, shared input classes, and softer loading/empty/error/notice states.
- Updated the app shell and Quick Add modal to feel calmer and more workspace-like.
- Updated dashboard cards/widgets and dashboard customization modal to use the softer card/button language.
- Updated `/sheets` with a softer workspace canvas, floating control panel, and calmer tile-like sheet cells while preserving the existing fixed 4x2 grid.
- Applied the shared page background treatment across major routes.
- Added `docs/UI_SYSTEM.md`.
- Updated `README.md` and `docs/UX_GUIDELINES.md`.

How to visually inspect it:
1. `docker compose up --build -d`
2. `docker compose exec backend alembic upgrade head`
3. `docker compose exec backend alembic current`
4. `docker compose exec backend pytest`
5. `docker compose exec frontend npm run build`
6. Open `/`, `/sheets`, `/tasks`, `/calendar`, `/notes`, `/tracker`, `/planning`, and `/search`.
7. Open Quick Add from the top navigation.
8. On `/sheets`, open the workspace dropdown and slot editor.

What success looks like:
- The app feels calmer and less like a default technical dashboard.
- Navigation is readable and softer.
- Dashboard widgets have a coherent card language.
- Sheet cells feel like workspace tiles, not harsh grid boxes.
- Forms, buttons, and common states feel more consistent.
- Existing behavior is unchanged.
- Backend tests and frontend build pass.

Intentionally postponed:
- No new product features.
- No backend behavior changes.
- No migrations.
- No auth, AI, notifications, reminders, or external integrations.
- No dark mode.
- No drag-and-drop, widget resizing, or sheet layout model changes.
- No full branding/logo system.
- No complete component library or design-system package.

Recommended next phase:
- Do a focused visual QA pass with screenshots of each major route.
- Gradually replace remaining one-off form/button/card classes with the shared UI primitives during future feature work.
- Consider a second UI polish pass for dense feature pages like Tasks, Notes, Calendar, and Tracker after this foundation settles.
