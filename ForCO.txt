Hi! This was a Phase 4 hardening pass for Tasks.

What got fixed:
- Weekly task occurrences can only be completed on dates matching the task's weekdays.
- The Tasks page now disables weekly completion checkboxes when a task is not scheduled for the selected date.
- The default Tasks date now uses your local browser date.
- Task API calls encode date query values safely.
- Backend tests now cover daily completion idempotency, weekly task editing, and invalid weekly occurrence dates.

How to test it on Windows:
1. Start Docker Desktop.
2. Open PowerShell in the repo root.
3. Run `docker compose up --build -d`.
4. Run `docker compose exec backend alembic upgrade head`.
5. Run `docker compose exec backend alembic current`.
6. Run `docker compose exec backend pytest`.
7. Run `docker compose exec frontend npm run build`.

What to check:
- Home: http://localhost:3000
- Notes: http://localhost:3000/notes
- Tasks: http://localhost:3000/tasks
- Backend health: http://localhost:8000/health
- Database health: http://localhost:8000/health/db

Success looks like:
- Daily tasks can be created, edited, completed, uncompleted, and archived.
- Weekly tasks can be created, edited, assigned weekdays, completed for valid dates, uncompleted, and archived.
- Weekly tasks not scheduled for the selected date show as not completable.
- Backend tests and frontend build pass.

Known limits:
- Weekly recurrence is still intentionally simple: weekday templates only.
- No priorities, subtasks, labels, reminders, notifications, calendar, tracker, AI, widgets, or sheets yet.

Next recommended phase:
- Phase 5: fixed dashboard.
