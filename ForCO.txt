Hi! This pass implements Palette + Empty Slot Quick Add v1.

What changed:
- Named the default/current accent palette `Robot Vanilla`.
- Added `DuckBerry` and `BozzyWheat` as simple frontend-only accent palette options.
- Added a small palette selector to the app shell.
- Stored the selected palette in browser `localStorage`; no backend storage or user account behavior was added.
- Moved key accent styling onto CSS variables so palette changes affect primary buttons, focus rings, nav hover/active states, eyebrows, pills, sheet add affordances, and selected slot accents.
- Empty slots on `/sheets` now show a soft plus/Add something affordance.
- Clicking an empty slot in normal sheet viewing mode opens the existing Quick Add modal.
- The existing Customize slots flow still handles widget/slot assignment, including empty slots.

How to inspect/test it:
1. `docker compose up --build -d`
2. `docker compose exec backend alembic upgrade head`
3. `docker compose exec backend alembic current`
4. `docker compose exec backend pytest`
5. `docker compose exec frontend npm run build`
6. Open `/sheets`.
7. Use Customize slots to clear a slot if no empty slot is visible.
8. Click the empty slot's Add something affordance and confirm Quick Add opens.
9. Open Customize slots and confirm empty slots can still be selected/configured there.
10. Switch between Robot Vanilla, DuckBerry, and BozzyWheat from the app shell palette selector.
11. Refresh the page and confirm the selected palette persists.

What success looks like:
- Palette changes are noticeable in accent areas and softly tint white surfaces without recoloring the whole app.
- Robot Vanilla matches the previous default visual direction.
- DuckBerry feels deep berry/lavender but calm.
- BozzyWheat feels muted wheat/olive/golden without harsh yellow.
- Empty sheet slots feel actionable but still fit the soft workspace style.
- Existing Quick Add behavior still works normally.
- No backend behavior changes, migrations, or new storage tables were introduced.
- Backend tests and frontend build pass.

Intentionally postponed:
- No backend palette preferences.
- No user accounts, auth, dark mode, custom color picker, per-sheet palettes, or per-widget palettes.
- No drag-and-drop, widget resizing, or `x/y/w/h` layout.
- No new product modules.

Recommended next phase:
- Visual QA the three palettes across `/`, `/sheets`, `/tasks`, `/calendar`, `/notes`, `/tracker`, `/planning`, and `/search`.
- Keep any future theme work small and token-based unless a broader design-system spec is written.
