Hi! This added Sheet Workspace Shell v1.

What changed:
- Reworked `/sheets` into a workspace-first page with one visible sheet at a time.
- Made the primary sheet surface a fixed desktop-first 4 columns x 2 rows grid.
- Reduced normal page scrolling on `/sheets` by making the sheet workspace fill the available viewport below the app shell.
- Kept each slot visually contained with internal clipping/scrolling for overflowing widget content.
- Added a top-center Workspace trigger and dropdown/control panel.
- Added dropdown links to Dashboard, Notes, Tasks, Calendar, Tracker, Planning, and Search.
- Wired the dropdown Quick Add button to the existing global Quick Add modal.
- Added sheet controls in the dropdown:
  - previous sheet
  - next sheet
  - current sheet selector
  - create sheet
  - rename sheet
  - delete sheet
  - reset default sheet
  - customize slots
- Kept previous/next controls visible in the main sheet workspace header.
- Kept delete safe by disabling last-sheet deletion in the UI and preserving the backend last-sheet protection.
- Replaced the old long side editor with a focused slot editor panel.
- The slot editor now clearly shows the active sheet and active slot.
- The slot editor lets you select a widget type, clear the slot, set task category filters, set task widget title overrides, and save all slots.
- Multiple instances of the same widget type remain supported because every slot still persists its own `widget_key` and `config_json`.
- Tightened compact widget rendering for the 4x2 grid:
  - daily task widgets show concise counts and short task lists
  - weekly task widgets show concise counts and scheduled task lists
  - calendar widgets show concise upcoming events
  - notes widgets show recent titles and previews
  - tracker widgets show water/activity/calorie summaries
  - empty/loading states stay short
- Left the normal dashboard widgets and dashboard customization behavior intact.
- No backend schema or migration was added.
- Updated README.md with the Sheet Workspace Shell v1 overview, top-center dropdown behavior, sheet navigation, slot editing behavior, limitations, future direction, and Windows PowerShell commands.

How I test it:
1. Start Docker Desktop.
2. Open PowerShell in the repo root.
3. Run `docker compose up --build -d`.
4. Run `docker compose exec backend alembic current`.
5. Run `docker compose exec backend pytest`.
6. Run `docker compose exec frontend npm run build`.
7. Check backend health at `http://localhost:8000/health`.
8. Check DB health at `http://localhost:8000/health/db`.
9. Open `http://localhost:3000/sheets`.
10. Confirm the 4x2 workspace fills the page area and does not turn into a long scrolling page.
11. Open the top-center Workspace dropdown.
12. Use its links to navigate to Dashboard, Notes, Tasks, Calendar, Tracker, Planning, and Search.
13. Use Quick Add from the dropdown and confirm the existing modal opens.
14. Create a second sheet, navigate previous/next, and use the sheet selector.
15. Rename a sheet.
16. Confirm deleting the last remaining sheet is not allowed.
17. Open Customize slots.
18. Pick a slot, choose Daily Tasks or Weekly Tasks, set a category filter and title override, and save.
19. Add duplicate Daily Tasks or Weekly Tasks widgets with different configs.
20. Refresh `/sheets` and confirm configs persisted.
21. Check existing pages: `/`, `/notes`, `/tasks`, `/calendar`, `/tracker`, `/planning`, `/search`, and `/sheets`.
22. Confirm Global Search still works.
23. Confirm dashboard customization still works on `/`.
24. Confirm task category filtering still works on `/tasks`.

What success looks like:
- Docker Compose starts cleanly.
- Backend health and DB health return healthy responses.
- Alembic reports the current head revision.
- Backend tests pass.
- Frontend build passes.
- `/sheets` feels like a contained workspace instead of a normal long management page.
- The sheet grid remains a stable 4x2 layout.
- Widget overflow stays inside cells.
- The top-center dropdown works reliably by click, not hover only.
- Main app areas are reachable from the sheet dropdown.
- Quick Add still opens from the sheet dropdown.
- Sheet previous/next, selector, create, rename, delete protection, and reset behavior work.
- Slot editing is clear, focused, and persists after refresh.
- Duplicate widget types with different task configs still work.
- The normal dashboard remains separate and stable.

Limitations:
- No drag-and-drop.
- No widget resizing.
- No `x/y/w/h` layout.
- No final animation system.
- No full command palette.
- No auth or user-specific sheets.
- No AI, semantic search, or pgvector.
- No external integrations.
- No notifications or reminders.
- No tracker categories.
- No database-defined widgets or plugin system.
- Mobile is still not heavily optimized.
- The no-scroll feeling is practical rather than absolute; very small viewports may still need browser-level scrolling.

Recommended next phase:
- Write a short sheet/widget contract doc that defines compact rendering rules and supported `config_json` by widget type.
- Add a small visual QA pass for `/sheets` across common desktop sizes.
- Then consider Sheet Layout v2 with explicit edit/view modes before starting drag-and-drop, resizing, or `x/y/w/h` placement.
